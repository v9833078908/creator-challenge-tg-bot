# Архитектура Creator Hero Bot

## Стек

- **Python 3.12** + **aiogram 3.x** (Bot API, long polling)
- **SQLite** через **SQLAlchemy 2 (async, aiosqlite)**; миграции — **Alembic**. Переход на Postgres позже = смена URL + драйвера (docker-compose уже готовит место под это)
- **APScheduler 3.x** (AsyncIOScheduler) — джобы по расписанию
- **pydantic-settings** — конфигурация из env
- Деплой: **Docker + docker-compose**
- Тесты: **pytest + pytest-asyncio**

## Запуск

Один процесс: polling + планировщик в одном event loop. Long polling — серверу не нужен публичный URL/SSL. Джобы создаются/пересоздаются при старте и при изменении потока (singleton-процесс, джобы не дублируются).

## Модель данных

> Мультипоточность заложена сразу: `stream_id` есть во всех таблицах. Деление на «потоки» в v1 не используется — одна запись-поток создаётся миграцией/командой.

```
streams        id, title, chat_id (unique), invite_link, timezone,
               settings_json, is_active, created_at
participants   id, stream_id→streams, tg_user_id (null до /start),
               username, full_name,
               status (approved|active|left|kicked),
               joined_at, left_at, kick_count
daily_reports  id, stream_id, participant_id, report_date (локальная дата),
               message_id, kind (link|forward|text), char_count,
               seq_number (№k за день), created_at
               UNIQUE(stream_id, participant_id, report_date)
penalties      id, stream_id, participant_id, reason (missed_report),
               issued_for_date, status (open|paid|expired|cancelled),
               issued_at, paid_at, paid_message_id, due_at
daily_counters stream_id, report_date, emoji, count   -- эмодзи дня + №k
```

## Ключевые потоки

### Приём `#пост` (handler → services.challenge)
1. Сообщение в группе, содержит `#пост`, автор — активный участник.
2. Edited-сообщения игнорируем (античит, как у оригинала).
3. Валидация: текст/подпись ≥ `MIN_POST_CHARS` **или** ссылка t.me **или** форвард из канала. Не прошло → реплай с подсказкой.
4. Идемпотентность: один отчёт на (stream, user, дата). Повторный — реплай «уже засчитано».
5. Записываем, инкрементим счётчик дня, реплай «№k из N + эмодзи дня».

### День → ночь (джобы, таймзона потока, по умолчанию Europe/Moscow)
- **21:00** — напоминание всем, кто не сдал (реплай/пост в группу со списком).
- **00:00** — закрытие дня: всем несдавшим выставляется `penalty` (due = +24ч), публикуется `#дайджест`.
- **20:00** — напоминание штрафникам с open-штрафами (группа; личка — v1.1).
- **00:05** — кик участников с просроченными штрафами (`status=kicked`; без unban — возврат только через `/approve` владельцем).

### Приём `#штраф`
Хештег + автор имеет open-штраф → `status=paid`, реплай-подтверждение. Факт доната не проверяем (как оригинал).

### Онбординг (whitelist)
1. Владелец в личке бота: `/approve @username` → участник `approved`. Для `kicked` — это же команда возврата (unban + сброс штрафов). `/revoke @username` — убрать из whitelist (для `approved`, не трогая вступивших).
2. Пользователь пишет боту `/start` в личке: если его юзернейм в whitelist → приветствие + бессрочная инвайт-ссылка на чат. Не в whitelist → вежливый отказ («челлендж закрытый, вас пока нет в списке»).
3. Пользователь вступает по ссылке → `active`, приветствие в группе.

### Выход/возврат (механика «свободной паузы»)
- Участник выходит из чата сам → `left`. Пока `left` — обязательств нет, джобы его пропускают (не попадает в N, напоминания, штрафы). Новые штрафы за дни вне чата не начисляются — даже если вышел на 5 минут в 23:55 (**осознанное решение: эксплойт «тактический выход» принят как фича, аудитория — друзья**).
- **Открытые штрафы НЕ аннулируются при выходе.** Возврат по бессрочной ссылке → `active`, открытые штрафы восстанавливаются с новым `due_at = возврат + PENALTY_GRACE_HOURS` — сначала отработай `#штраф`, иначе кик по стандартному циклу.
- Накопленные Telegram updates обрабатываются перед запуском расписания.
  Пропущенные закрытия дней восстанавливаются по истории членства и отмечаются
  в `daily_closures`. При первом запуске новой схемы автоматически закрывается
  только вчерашний день, если поток уже существовал.

### Кик и возврат после кика
- Кик = `banChatMember` **без** `unban`: участник остаётся в чёрном списке чата, инвайт-ссылка для него не работает.
- Возврат только через владельца: `/approve @username` в личке → бот делает `unbanChatMember`, статус `kicked → approved`, штрафы обнуляются; пользователь пишет боту `/start` и получает ссылку заново.

| Кик просрочивших | `KICK_TIME` | `00:05` |
| ID владельца (админ) | `OWNER_TG_ID` | — |

## Нефункциональное

- **Идемпотентность** везде: джобы перезапускаемы без двойных штрафов (проверка по статусам/датам).
- **Мягкая деградация**: бот не админ в чате → кик заменяется сообщением владельцу; ошибки отправки логируются, джоб не падает.
- **Логи**: structlog/logging в stdout → docker logs.
- Том SQLite — volume в compose, бэкап = копия файла.
