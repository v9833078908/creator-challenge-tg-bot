# Creator Hero Bot

Telegram-бот для небольшого сообщества авторов, которые хотят публиковать контент регулярно. Участники отправляют ежедневные отчёты, бот напоминает о публикациях, подводит итоги дня и помогает сохранять ритм.

Проект работает с одной Telegram-группой. Polling, расписание и SQLite находятся в одном процессе; для самого бота не нужны домен, HTTPS и входящие порты.

## Возможности

- Доступ по списку участников, которым управляет организатор.
- Ежедневные отчёты с `#пост`: текст, ссылка на публикацию в Telegram или пересланный пост канала.
- Напоминания, дайджесты и статистика участия.
- Один открытый штраф на участника: новые пропуски не накапливают долг и не продлевают его срок.
- Пауза при самостоятельном выходе из группы с сохранением истории.
- Личная программа из 33 уроков с независимым прогрессом каждого участника.
- Восстановление расписания и состояния после перезапуска.
- Миграции Alembic и проверяемые резервные копии SQLite.

Вход остаётся дружеским: неизвестный гость по общей ссылке остаётся в группе, а организатор получает уведомление. Пока гость не одобрен, он не участвует в статистике, напоминаниях и штрафах. Привязка участника к Telegram ID сохраняется при смене username.

## Быстрый запуск

Понадобятся Docker с плагином Docker Compose, токен от [@BotFather](https://t.me/BotFather) и Telegram ID организатора.

```bash
git clone https://github.com/v9833078908/creator-challenge-tg-bot.git
cd creator-challenge-tg-bot
cp .env.example .env
```

Заполните в `.env`:

| Переменная | Значение |
| --- | --- |
| `BOT_TOKEN` | Токен вашего бота |
| `OWNER_TG_ID` | Telegram user ID организатора, не username и не ID группы |

Остальные параметры описаны в [`.env.example`](.env.example). Затем запустите контейнер:

```bash
docker compose up -d --build
docker compose logs -f bot
```

Миграции применяются автоматически. Проверить состояние:

```bash
docker compose ps
```

**Один токен — один polling-процесс.** Перед запуском убедитесь, что этот токен не используется другим экземпляром бота. Данные хранятся в Docker volume `creator-bot-data`; пересборка контейнера их не удаляет.

### Подключение группы

1. Добавьте бота в группу администратором с правами приглашать и блокировать участников.
2. От имени организатора отправьте `/init_stream` в группе.
3. Напишите боту в личку `/approve @username`, чтобы одобрить участника.
4. Участник пишет боту `/start` в личке и получает ссылку на группу.
5. После вступления участник отправляет ежедневные отчёты с `#пост`.

Владелец самой Telegram-группы освобождён от автоматических обязательств и личной рассылки уроков. Обычные администраторы участвуют на общих условиях. Права управления ботом отдельно определяются настройкой `OWNER_TG_ID`.

## Правила челленджа

По умолчанию дедлайн — **23:59 по Europe/Moscow**. Отчёт должен содержать `#пост` и одно из следующего:

- текст длиной не менее 400 символов;
- ссылку `t.me`;
- пересланную публикацию канала.

За день засчитывается один отчёт. Редактирование сообщения не пересчитывает результат: исправленный отчёт нужно отправить новым сообщением.

За пропуск назначается штраф: донат 500 ₽ или видео с 30 бёрпи. Сообщение с `#штраф` закрывает открытый штраф; подтверждение доната бот не проверяет. На отработку даются 24 часа, после истечения срока участник исключается при следующем запуске проверки просроченных штрафов.

Самостоятельный выход приостанавливает участие, но не отменяет открытый штраф. При возвращении срок его отработки начинается заново; новые штрафы за время отсутствия не начисляются. После исключения возвращение разрешает организатор через `/approve`.

### Расписание по умолчанию

| Время потока | Действие |
| --- | --- |
| 00:00 | Закрытие дня, дайджест и назначение штрафов |
| 00:05 | Исключение участников с просроченным штрафом |
| 18:00 | Напоминание тем, кто ещё не отправил отчёт |
| 20:00 | Напоминание об открытых штрафах |

Часовой пояс, дедлайн, расписание, минимальная длина поста и параметры штрафа настраиваются через переменные окружения.

## Личная программа уроков

Программа содержит 33 урока и 12 дополнительных материалов. Одобренный участник активирует её командой `/start` в личке:

- первый урок приходит через 10 минут после первой активации;
- следующие — в 08:00 по московскому времени, не более одного за московскую дату;
- повторный `/start` не сбрасывает прогресс;
- выход, исключение или отзыв доступа приостанавливают доставку;
- после простоя уроки продолжаются по порядку, без пачки пропущенных сообщений.

Уроки и небольшие практические шаги необязательны: дополнительной отчётности и штрафов нет. Бот присылает короткий анонс и кнопку на публичную статью. Каталог анонсов и ссылок находится в [`bot/data/lesson-catalog.json`](bot/data/lesson-catalog.json).

Статьи размещаются отдельно от бота. Для собственного размещения доступны примеры в [`infra/writefreely/`](infra/writefreely/); домен, сертификаты и серверные пути в шаблонах нужно адаптировать. Полные тексты, PDF, аудио и рабочие выгрузки курса в репозиторий не включены.

## Команды

| Команда | Где | Назначение |
| --- | --- | --- |
| `/start` | Личка | Получить доступ и активировать личную программу |
| `/init_stream` | Группа | Привязать группу; только организатор |
| `/approve @username` | Личка | Одобрить участника или разрешить возврат после исключения |
| `/approve TelegramID` | Личка | Восстановить доступ уже привязанного аккаунта |
| `/revoke @username` или `/revoke TelegramID` | Личка | Отозвать доступ ещё не вступившего участника |
| `/stats` | Личка | Посмотреть статистику потока |
| `/course_status @username` или `/course_status TelegramID` | Личка | Посмотреть прогресс уроков |
| `/resolve_lesson @username sent` или `retry` | Личка | Вручную разрешить неоднозначный результат отправки |

Все управляющие команды доступны только `OWNER_TG_ID`. Для `/resolve_lesson` также поддерживается Telegram ID. Перед `retry` организатор должен уточнить у участника, не пришёл ли урок: повтор может создать дубликат.

## Разработка

Стек: **Python 3.12, aiogram 3, APScheduler, SQLAlchemy, Alembic и SQLite**.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.lock
python -m pip install -e '.[dev]'
pytest -q
ruff check .
```

Для локального запуска вместо Docker настройте `.env` и выполните:

```bash
python -m bot
```

Предварительно остановите другие экземпляры с тем же токеном. Тесты используют изолированные базы и не требуют рабочего Telegram-токена. GitHub Actions запускает тесты, Ruff и сборку Docker-образа.

### Структура проекта

| Путь | Назначение |
| --- | --- |
| `bot/handlers/` | Команды и события Telegram |
| `bot/services/` | Правила челленджа, отчёты, уроки и тексты |
| `bot/scheduler/` | Расписание и восстановление задач |

Архитектура и переходы состояний описаны в [`docs/architecture.md`](docs/architecture.md). Перед работой агента с кодом прочитайте [`agent.md`](agent.md).

## Деплой и резервные копии

Процедуры установки на VPS, обновления, переноса данных и восстановления — в [`docs/deploy.md`](docs/deploy.md).

Создать согласованную резервную копию SQLite с проверкой целостности:

```bash
./scripts/backup.sh                 # локальный Docker volume
./scripts/backup.sh user@your-vps   # скачать копию с VPS
```

Копии сохраняются в `backups/`. Перед миграцией или восстановлением сделайте и проверьте свежий бэкап. Для восстановления рабочего volume:

```bash
./scripts/restore.sh backups/creator-bot-YYYY-MM-DD_HH-MM-SS.db
```

Скрипт останавливает контейнер перед заменой БД и запускает его после восстановления. Серверный `.env`, каталог `backups/` и volume с данными нужно сохранять при обновлениях.
